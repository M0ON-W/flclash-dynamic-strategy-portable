# 項目總結

## 目標

在 FlClash 上建立三個持久、中文、動態更新的策略組，並以獨立 Mihomo TUN 服務承擔開機後的底層路由，使訂閱更新、FlClash 重啟或短暫關閉不會永久移除策略能力。

## 最終組成

1. `strategy_manager.py`
   - 讀取 FlClash 當前配置和節點。
   - 建立 `净选`、`稳净`、`极速`及隱藏的 `__谷歌AI`、`__OpenAI`。
   - 寫入 FlClash 覆寫腳本、DNS、規則和健康檢查。
   - 建立每節點本機監聽器，供互不串線的檢測使用。
   - 保存歷史樣本、分類結果、Google/Gemini 測速和最近狀態。
   - 應用新配置後檢查連通性；失敗時恢復上一份可用配置。

2. `FlClashMihomoService`
   - 由 WinSW 2.12.0 包裝 Mihomo 1.19.30。
   - 以 LocalSystem、自動延遲啟動和故障重啟方式運行。
   - 使用獨立端口和 `MihomoSvc` TUN，避免與 FlClash 核心衝突。
   - 將 FlClash 本身的程序流量設為直連，避免雙重代理迴圈。

3. `FlClash-Strategy-20min`
   - 使用 `pythonw.exe` 靜默執行，不建立終端視窗。
   - 每 20 分鐘更新；登入時也會執行一次。
   - FlClash 在線時同步兩套核心；FlClash 離線但獨立服務在線時，仍可透過獨立節點監聽器累積樣本。

4. `FlClash-Elevated-AtLogon`
   - 以最高權限在使用者登入後啟動 FlClash。
   - 取代重複的 HKCU Run 啟動項，避免同一程序被啟動多次。

## 已處理的主要問題

- 清除舊覆寫後，三個策略組可由腳本穩定重建。
- 掃描品質不足或任一受管組歸零時拒絕候選，並恢復最近一次完整非空快照。
- 死鎖檔會結合 PID 判斷後清理，避免排程永久停止。
- 所有 curl 子程序以 Windows 無視窗旗標啟動，避免大量終端視窗。
- `稳净`改為保存 7 天、504 個樣本，不再只保留短期樣本；216 個樣本前維持暫定狀態。
- `极速`與 Google/Gemini 專用組使用按排序的 `fallback`，優先使用管理器排名，同時保留故障切換。
- Google/Gemini 使用專用動態出口池；候選需連續通過搜尋無區域重定向、GStatic、帳號頁及 Gemini 檢測，主備優先保持相同出口 IP。
- Google 或 OpenAI 連接活躍時暫緩熱加載；安全套用失敗會連同狀態、DNS 偏好、獨立服務配置及覆寫腳本一起回復。
- 獨立 TUN 啟用具備狀態核對與失敗回滾。
- 哔哩哔哩主站、API、圖片與視頻 CDN 域名固定直連並排除 fake-IP；驗收同時檢查 7890 代理入口與獨立 TUN 訪問。
- `__谷歌AI` 與 `__OpenAI` 屬可選專用池；候選暫時為空或已不在目前訂閱時，自動回退到 `极速`，不阻斷一般代理路由或排程更新。
- 國內直連網域的 AliDNS DoH 同樣直連，避免海外 DNS 出口返回不適配本地線路的 CDN；Bilibili 的 `bilicdn1.com` 等 CNAME 目標亦納入同一策略。
- `MihomoSvc` TUN MTU 固定為 1400，避免虛擬網卡 MTU 9000 經 WLAN 1500 時造成 DNS 大回應、TLS 握手及長連線分片異常。

## 當前項目的解讀邊界

此系統是持續觀測和動態決策系統，不是節點品質製造器。供應商擁塞時，它只能在可用候選中選擇相對較好者；不能把實際吞吐提升到供應商標稱帶寬，也不能保證任何外部服務永遠不改變風控判定。
