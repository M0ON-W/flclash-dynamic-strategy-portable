# 技術架構

## 端口與程序

| 元件 | 端口/名稱 | 用途 |
|---|---:|---|
| FlClash mixed | 7890 | 日常系統代理入口 |
| FlClash controller | 9090 | 本機配置與健康檢查 API |
| FlClash 節點監聽器 | 23000–23179 | 每節點隔離檢測 |
| 獨立 Mihomo mixed | 17890 | 獨立服務代理入口 |
| 獨立 controller | 19090 | 獨立服務管理 API |
| 獨立 DNS | 11053 | 獨立 TUN DNS |
| 獨立節點監聽器 | 33000–33179 | FlClash 離線時檢測 |
| 獨立 TUN | MihomoSvc | 自動路由與 DNS 劫持 |

所有代理和控制端口只綁定 `127.0.0.1`，`allow-lan`關閉。

## 策略組

### 净选

節點必須同時通過 Cloudflare、Google、OpenAI 和 Gemini 的服務可用性檢查，並符合出口信譽條件。排序依次考慮風險值、延遲和測得速度。這是檢測時刻的嚴格結果，不代表永久保證。

### 稳净

- 掃描週期：20 分鐘。
- 滾動窗口：7 天，共 504 個樣本。
- 最短成熟期：3 天，共 216 個樣本。
- 成熟條件：在線率至少 99%、嚴格潔淨率 100%、最新樣本仍嚴格潔淨、中位延遲不高於 500 ms、中位速度至少 5 Mbps。
- 尚無成熟節點時，使用當前嚴格潔淨節點作暫定名單，`stable_provisional=true`；此時預設 MATCH 仍使用 `极速`。
- 一旦有成熟節點，預設 MATCH 自動切換到 `稳净`。

### 极速

在線節點按歷史中位速度與延遲的綜合分數排序，保留前 20 個，使用 `fallback`依序選擇並在故障時切換。策略組每 10 分鐘使用 128 KiB Cloudflare 下載作健康檢查。

### Google/Gemini 專用組

Google、Google APIs 和 GStatic 全部路由到隱藏組 `__谷歌AI`。全新安裝先以三個非空引導節點完成首次掃描，之後將同時通過嚴格信譽與服務檢測的節點自動加入 Google 驗證池。候選節點必須讓 Google 搜尋首頁直接返回 200 且不發生區域重定向，同時通過 GStatic 204、Google 帳號同站跳轉與 Gemini 200 檢測，並排除風控提示頁。新出口至少連續通過兩輪才可加入；主節點與備援優先限制在相同出口 IP，出口身份改變時重新累積驗證。候選以受限並行方式執行 1 MiB 測速，不需要從原電腦複製節點名單。

### OpenAI/ChatGPT 專用組

OpenAI、ChatGPT 域名及 MetaCubeX 提供器路由到隱藏組 `__OpenAI`，由同時通過 Cloudflare、Google、OpenAI（返回 401 驗證碼）及 Gemini 檢測的潔淨節點構成。當偵測到有活躍的 Google 或 OpenAI/ChatGPT 連接時，系統會暫緩策略熱加載，避免同一工作階段中途切換出口。

### 掃描品質與最後可用狀態

每輪掃描先在候選狀態中分類。若在線節點低於最低比例，或 `净选`、`稳净`、`极速`、`__谷歌AI`、`__OpenAI`任一組歸零，結果會被拒絕並恢復最近一次完整非空快照。空組不再由其他服務組跨標準填充。安全套用會逐組使用獨立節點監聽器驗證；失敗時同時恢復 FlClash 運行配置、管理狀態、DNS 偏好、獨立服務配置及覆寫腳本。

## 規則分流體系 (MetaCubeX MRS)

採用 Mihomo 原生 MRS 規則集提供器（每日自動更新並本機快取）：
1. 本機與局域網 -> `DIRECT`
2. OpenAI (`openai.mrs`) -> `__OpenAI`
3. Gemini / Google AI (`google-gemini.mrs`) -> `__谷歌AI`
4. 其他非中國 AI (`category-ai-!cn.mrs`) -> `净选`
5. 普通 Google 服務 (`google.mrs`) -> `__谷歌AI`
6. 微軟中國區 (`microsoft@cn.mrs`)、蘋果中國區 (`apple-cn.mrs` 及 `*.apple.com.cn`, `*.icloud.com.cn`) -> `DIRECT`
7. 國際微軟 (`microsoft.mrs`)、國際蘋果 (`apple.mrs`) -> `极速`
8. 中國域名 (`cn.mrs`)、中國 IP (`geoip/cn.mrs`) -> `DIRECT`
9. Cloudflare -> `净选`
10. 其他未分類流量 -> 預設路由 (`极速` / `稳净`)

## DNS

- `enhanced-mode: fake-ip`
- fake-IP 網段 `198.18.0.1/16`
- DoH 上游 `1.1.1.1`與 `8.8.8.8`
- `respect-rules: true`
- `use-system-hosts: false`
- IPv6 關閉
- TUN 劫持 UDP/TCP 53
- DoH 請求透過已選 DNS 代理節點發出
- **國內分流 DNS 策略**：針對中國域名規則集（`__managed-cn`、`__managed-microsoft-cn`、`__managed-apple-cn`、`+.apple.com.cn`、`+.icloud.com.cn`）配置 AliDNS 加密 DoH（`https://223.5.5.5/dns-query`、`https://223.6.6.6/dns-query`），透過 `极速`代理節點發送，不注入合成 ECS。

這些設定防止一般系統 DNS 直接外洩，但外部網站仍可從帳戶、瀏覽器、時區、語言、WebRTC、付款資料或既有 Cookie 推斷地區；DNS 設定不能抹除這些非 DNS 訊號。

## 持久化資料

位於：

```text
%APPDATA%\com.follow\clash\managed
```

- `strategy_manager.py`：實際排程執行副本。
- `state.json`：分組、歷史、出口信譽、Gemini 測速、TUN 狀態。
- `latest_status.json`：最近一次執行結果。
- `manager.log`：輪轉日誌。
- `last-known-good.yaml`：最近一次安全應用前的可用配置。
- `mihomo-service\config.yaml`：獨立服務配置。

訂閱更新後，排程會根據新節點名稱過濾舊成員並重新分類；歷史資料按節點名稱關聯。

## 安全應用流程

1. 保存當前核心模式、TUN 狀態和 GLOBAL 選擇。
2. 生成候選配置並透過 9090 熱重載，不關閉 FlClash。
3. 驗證原選擇與各策略組的 Cloudflare/Google/OpenAI/Gemini 連通性。
4. 檢查失敗時恢復 `last-known-good.yaml`及原選擇。
5. 通過後同步獨立服務配置。
