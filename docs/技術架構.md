# 技术架构

## 端口与进程

| 元件 | 端口/名称 | 用途 |
|---|---:|---|
| FlClash mixed | 7890 | 日常系统代理入口 |
| FlClash controller | 9090 | 本机配置与健康检查 API |
| FlClash 节点监听器 | 23000–23179 | 每节点隔离检测 |
| 独立 Mihomo mixed | 17890 | 独立服务代理入口 |
| 独立 controller | 19090 | 独立服务管理 API |
| 独立 DNS | 11053 | 独立 TUN DNS |
| 独立节点监听器 | 33000–33179 | FlClash 离线时检测 |
| 独立 TUN | MihomoSvc | 自动路由与 DNS 劫持 |

所有代理和控制端口只绑定 `127.0.0.1`，`allow-lan` 关闭。

## 策略组

共三组可见策略组和三个隐藏专用组，定义位置在 `src/strategy_manager.py` 顶部的常量区（`GROUP_CLEAN`、`GROUP_STABLE`、`GROUP_FAST`、`GROUP_GOOGLE_AI`、`GROUP_OPENAI`、`GROUP_NETFLIX`，运行时集合为 `RUNTIME_GROUPS`）。

### 净选

节点必须同时通过 Cloudflare、Google、OpenAI 和 Gemini 的服务可用性检查，并符合出口信誉条件。排序依次考虑风险值、延迟和测得速度。这是检测时刻的严格结果，不代表永久保证。

### 稳净

- 扫描周期：20 分钟。
- 滚动窗口：7 天，共 504 个样本。
- 最短成熟期：3 天，共 216 个样本。
- 成熟条件：在线率至少 99%、严格洁净率 100%、最新样本仍严格洁净、中位延迟不高于 500 ms、中位速度至少 5 Mbps。
- 尚无成熟节点时，使用当前严格洁净节点作暂定名单，`stable_provisional=true`；此时默认 MATCH 仍使用 `极速`。
- 一旦有成熟节点，默认 MATCH 自动切换到 `稳净`。

### 极速

在线节点按历史中位速度与延迟的综合分数排序，保留前 20 个，使用 `fallback` 依序选择并在故障时切换。策略组每 10 分钟使用 128 KiB Cloudflare 下载作健康检查。

### Google/Gemini 专用组

Google、Google APIs 和 GStatic 全部路由到隐藏组 `__谷歌AI`。全新安装先以三个非空引导节点完成首次扫描，之后将同时通过严格信誉与服务检测的节点自动加入 Google 验证池。候选节点必须让 Google 搜索首页直接返回 200 且不发生区域重定向，同时通过 GStatic 204、Google 账号同站跳转与 Gemini 200 检测，并排除风控提示页。新出口至少连续通过两轮才可加入；主节点与备援优先限制在相同出口 IP，出口身份改变时重新累积验证。候选以受限并行方式执行 1 MiB 测速，不需要从原电脑复制节点名单。

`DEFAULT_GOOGLE_BLOCKED_MEMBERS` 列出的节点会被排除在 Google 严格池之外，避免与 Netflix 固定出口抢占同一条线路。

### OpenAI/ChatGPT 专用组

OpenAI、ChatGPT 域名及 MetaCubeX 提供器路由到隐藏组 `__OpenAI`，由同时通过 Cloudflare、Google、OpenAI（返回 401 验证码）及 Gemini 检测的洁净节点构成。当检测到有活跃的 Google 或 OpenAI/ChatGPT 连接时，系统会暂缓策略热加载，避免同一工作会话中途切换出口。

### Netflix 专用组

Netflix 域名（`netflix.com`、`nflxvideo.net`、`nflximg.net`、`nflxso.net`、`nflxext.com`）与 `__managed-netflix` 规则集路由到隐藏组 `__Netflix`。成员由固定节点模式选定（`NETFLIX_PIN_PATTERNS` 匹配指定美国线路），不参与全网排序：

- 候选池：命中模式且最近 7 天内至少有一次在线记录。
- 触发条件：Netflix 域名连接中断超过 `NETFLIX_GAP_SECONDS`（120 秒）才判定出现播放空档；有活跃连接时不切换。
- 资格：7 天在线率不低于 0.90、24 小时在线率不低于 0.80，并逐个探测，延迟须低于 `NETFLIX_MAX_LATENCY_MS`（1500 ms）。
- 排序与保持：先按 7 天在线率，再按延迟；当前出口仍合格且优势不足 `NETFLIX_BETTER_MARGIN`（0.30）时保持不动。
- 冷却：`NETFLIX_PIN_COOLDOWN_SECONDS`（4 小时）内不重复钉选。
- 生效：同时通过 FlClash 控制器与独立 Mihomo 控制器执行 `PUT /proxies/__Netflix`，结果写入 `state.json` 的 `netflix_members`、`netflix_selected`、`netflix_last_pin_at`。

## 扫描质量与最后可用状态

每轮扫描先在候选状态中分类。若在线节点低于最低比例，或 `净选`、`稳净`、`极速`、`__谷歌AI`、`__OpenAI`、`__Netflix` 任一受管组归零，结果会被拒绝并恢复最近一次完整非空快照。空组不再由其他服务组跨标准填充。安全套用会逐组使用独立节点监听器验证；失败时同时恢复 FlClash 运行配置、管理状态、DNS 偏好、独立服务配置及覆写脚本。

## 规则分流体系 (MetaCubeX MRS)

采用 Mihomo 原生 MRS 规则集提供器（每日自动更新并本机缓存）：

1. 本机与局域网 -> `DIRECT`
2. OpenAI (`openai.mrs`) -> `__OpenAI`
3. Gemini / Google AI (`google-gemini.mrs`) -> `__谷歌AI`
4. 其他非中国 AI (`category-ai-!cn.mrs`) -> `净选`
5. Netflix (`netflix.mrs`) -> `__Netflix`
6. 普通 Google 服务 (`google.mrs`) -> `__谷歌AI`
7. 微软中国区 (`microsoft@cn.mrs`)、苹果中国区 (`apple-cn.mrs` 及 `*.apple.com.cn`、`*.icloud.com.cn`) -> `DIRECT`
8. 国际微软 (`microsoft.mrs`)、国际苹果 (`apple.mrs`) -> `极速`
9. 中国域名 (`cn.mrs`)、中国 IP (`geoip/cn.mrs`) -> `DIRECT`
10. Cloudflare -> `净选`
11. 其他未分类流量 -> 默认路由 (`极速` / `稳净`)

`__managed-*` 规则集由 `MANAGED_RULESETS` 统一定义，来源为 MetaCubeX meta-rules-dat。

## DNS

- `enhanced-mode: fake-ip`
- fake-IP 网段 `198.18.0.1/16`
- DoH 上游 `1.1.1.1` 与 `8.8.8.8`
- `respect-rules: true`
- `use-system-hosts: false`
- IPv6 关闭
- TUN 劫持 UDP/TCP 53
- DoH 请求通过已选 DNS 代理节点发出
- **国内分流 DNS 策略**：针对中国域名规则集（`__managed-cn`、`__managed-microsoft-cn`、`__managed-apple-cn`、`+.apple.com.cn`、`+.icloud.com.cn`）配置 AliDNS 加密 DoH（`https://223.5.5.5/dns-query`、`https://223.6.6.6/dns-query`），通过 `极速` 代理节点发送，不注入合成 ECS。
- **强制直连域名**：`DIRECT_DOMAINS`（`maitokens.top`、`maitokens.com`）在规则里写出 `DOMAIN-SUFFIX,...,DIRECT`，在 DNS 里使用国内 DoH 直连解析，且排除 fake-IP。

这些设置防止一般系统 DNS 直接外泄，但外部网站仍可从账户、浏览器、时区、语言、WebRTC、付款资料或既有 Cookie 推断地区；DNS 设置不能抹除这些非 DNS 信号。

## 持久化数据

位于：

```text
%APPDATA%\com.follow\clash\managed
```

- `strategy_manager.py`：实际排程执行副本（由 `src/strategy_manager.py --install` 写入）。
- `state.json`：分组、历史、出口信誉、Gemini 测速、TUN 状态、Netflix 钉选状态。
- `latest_status.json`：最近一次执行结果。
- `manager.log`：轮转日志。
- `last-known-good.yaml`：最近一次安全应用前的可用配置。
- `mihomo-service\config.yaml`：独立服务配置。
- `google-observer\`：观察器状态与报告。

订阅更新后，排程会根据新节点名称过滤旧成员并重新分类；历史数据按节点名称关联。

## 安全应用流程

1. 保存当前核心模式、TUN 状态和 GLOBAL 选择。
2. 生成候选配置并通过 9090 热重载，不关闭 FlClash。
3. 验证原选择与各策略组的 Cloudflare/Google/OpenAI/Gemini 连通性。
4. 检查失败时恢复 `last-known-good.yaml` 及原选择。
5. 通过后同步独立服务配置。

## 观察器子系统（只读）

`src/google_observer.py` 由独立排程 `FlClash-Google-Observer-20min` 运行，部署在 `managed\google-observer\`：

- 只读取正式状态和节点监听器，所有输出写入 `managed\google-observer`。
- 不调用控制器配置接口、不修改正式 `state.json`、FlClash 数据库、覆写脚本、DNS 或任何策略组。
- 出口身份使用本机随机密钥生成的 HMAC 标识，报告不含节点名、出口 IP、订阅地址或账号内容。
- 观察满 24 小时且达到完整性门槛后仍只产出候选报告，`atomic_switch_ready` 不会自动切换真实 Google 流量。

## 仓库结构与真源

| 路径 | 说明 |
| --- | --- |
| `src/` | 唯一真源：`strategy_manager.py` 与 `google_observer.py` |
| `tests/` | 单元测试；`conftest.py` 把 `src/` 加入导入路径 |
| `scripts/` | 安装、验收、回滚、运行时校验、观察器安装卸载、校验值生成 |
| `docs/` | 架构、安装迁移、项目总结、观察器说明、历史发布说明 |
| `assets/` | 配置样例（Shadowrocket 三组扩展、覆写脚本预览） |
| `egern/` | 手机端 Egern 移植与校验脚本 |
| `bin/`、`licenses/` | 可移植包自带的二进制与许可证 |
| `_local/` | 被 .gitignore 忽略的本机私有区 |

- 部署：改完 `src/strategy_manager.py` 后运行 `python src\strategy_manager.py --install`，脚本会先把自身复制到 `managed\`；`managed\` 下的副本是产物，不要直接改。
- 测试：`python -m pytest tests -q`。
- 校验值：`scripts/Update-Checksums.ps1` 重新生成 `SHA256SUMS.txt`（按 git 跟踪文件，排除 `.github/` 与文件自身）。
